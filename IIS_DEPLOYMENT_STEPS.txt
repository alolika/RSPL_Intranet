=====================================================================
  RSPL INTRANET - PUBLISH ON IIS (LOCAL WINDOWS SERVER)
  Step-by-step guide
=====================================================================

HOW IT WORKS
------------
  Browser  --->  IIS (port 80)
                  |-- /            -> Angular files (C:\rspl\web)
                  |-- /proxy/...   -> FastAPI backend (127.0.0.1:8010)
                  |-- /face-photos -> FastAPI backend (127.0.0.1:8010)

  - IIS serves the Angular app and forwards API calls to the backend.
  - The backend (Python FastAPI) runs as a Windows service on the same
    server, listening only on 127.0.0.1 (not reachable directly from LAN).
  - Browser talks only to IIS, so no CORS problems.

  Folders used in this guide (change if you like):
    C:\rspl\rspl_Api   -> backend
    C:\rspl\web        -> frontend (Angular build output)


=====================================================================
PART A - ONE-TIME SERVER SETUP
=====================================================================

STEP A1. Install IIS
  1. Open "Turn Windows features on or off"
     (Windows Server: Server Manager > Add Roles and Features).
  2. Tick: Internet Information Services
       > Web Management Tools > IIS Management Console
       > World Wide Web Services > Common HTTP Features
           > Default Document
           > Static Content
           > HTTP Errors
  3. Click OK and wait for install to finish.
  4. Test: open http://localhost on the server -> IIS welcome page.

STEP A2. Install URL Rewrite module
  1. Download: https://www.iis.net/downloads/microsoft/url-rewrite
  2. Run the installer.

STEP A3. Install Application Request Routing (ARR) 3.0
  1. Download: https://www.iis.net/downloads/microsoft/application-request-routing
  2. Run the installer.
  3. Enable proxy (IMPORTANT - without this API calls fail with 404/502):
       IIS Manager > click the SERVER name (top node, left panel)
       > double-click "Application Request Routing Cache"
       > right panel: "Server Proxy Settings..."
       > tick "Enable proxy" > click Apply (right panel).

STEP A4. Install Python
  1. Download Python 3.12 (64-bit) from https://www.python.org/downloads/
  2. During install tick "Add python.exe to PATH".
     Choose "Install for all users" (so the service account can use it).
  3. Test in a new Command Prompt:   python --version

STEP A5. Install Microsoft ODBC Driver 17 for SQL Server
  1. Download: https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server
     (choose "ODBC Driver 17", x64)
  2. Run the installer.

STEP A6. Install NSSM (runs the backend as a Windows service)
  1. Download: https://nssm.cc/download  (nssm 2.24)
  2. Extract, copy  win64\nssm.exe  to  C:\Windows\System32\
  3. Test in Command Prompt:   nssm version

STEP A7. Check database access from the server
  In PowerShell on the server:
     Test-NetConnection retailware.no-ip.org -Port 1954
  "TcpTestSucceeded : True" is required.
  NOTE: inside the office LAN use  retailware.no-ip.org  (resolves to
  192.168.200.37). The public IP 47.247.158.18 does NOT work from inside
  the office.


=====================================================================
PART B - BACKEND (rspl_Api)
=====================================================================

STEP B1. Copy the backend to the server
  Copy these from D:\Maruti_workspace\rspl_Api to C:\rspl\rspl_Api :
     app\                 (whole folder)
     requirements.txt
     .env
     face_photos\         (if it exists)
  Do NOT copy: .venv, *.log files.

STEP B2. Check the .env file (C:\rspl\rspl_Api\.env)
  Make sure these lines are correct:
     DB_SERVER=retailware.no-ip.org
     DB_PORT=1954
     DB_NAME=worldnettech
     DB_USER=sa
     DB_PASSWORD=<keep existing>
     JWT_SECRET=<keep existing>
  Add the IIS address to CORS_ORIGINS (harmless, useful for testing):
     CORS_ORIGINS=http://localhost,http://<SERVER-IP>

STEP B3. Create the Python environment and install packages
  Open Command Prompt AS ADMINISTRATOR:
     cd /d C:\rspl\rspl_Api
     python -m venv .venv
     .venv\Scripts\pip install -r requirements.txt

STEP B4. Test the backend manually (before making it a service)
     .venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8010
  Open http://127.0.0.1:8010/docs in a browser on the server.
  You should see the API documentation page.
  Press Ctrl+C to stop it.

STEP B5. Install the backend as a Windows service
  In Command Prompt AS ADMINISTRATOR:
     nssm install RSPL_Api "C:\rspl\rspl_Api\.venv\Scripts\python.exe" "-m uvicorn app.main:app --host 127.0.0.1 --port 8010"
     nssm set RSPL_Api AppDirectory C:\rspl\rspl_Api
     nssm set RSPL_Api Start SERVICE_AUTO_START
     nssm set RSPL_Api AppStdout C:\rspl\rspl_Api\service.log
     nssm set RSPL_Api AppStderr C:\rspl\rspl_Api\service.log
     nssm start RSPL_Api
  Check: services.msc -> "RSPL_Api" status = Running.
  Check again: http://127.0.0.1:8010/docs opens.

PART C - FRONTEND BUILD (on the developer PC, D:\Maruti_workspace)
=====================================================================

  The normal production build points the API to the LIVE CapRover backend
  (https://rsplintranet-backend.apps.retailware.in). For IIS it must use
  "/proxy" instead. Create a separate "local" build so the live build is
  not affected.

STEP C1. Create file  rspl_Angular\src\environments\environment.local.ts
  with this content:

     export const environment = {
       production: true,
       apiBaseUrl: '/proxy',
     };

STEP C2. Add a "local" configuration in  rspl_Angular\angular.json
  Inside  projects > rspl_Angular > architect > build > configurations,
  next to the existing "production" block, add:

            "local": {
              "budgets": [
                { "type": "initial", "maximumWarning": "1.5MB", "maximumError": "3MB" },
                { "type": "anyComponentStyle", "maximumWarning": "4kB", "maximumError": "8kB" }
              ],
              "outputHashing": "all",
              "fileReplacements": [
                {
                  "replace": "src/environments/environment.ts",
                  "with": "src/environments/environment.local.ts"
                }
              ]
            },

  (Same as the existing "production" block - only the environment file
   differs. Mind the comma between "production": {...} and "local": {...}.)

STEP C3. Create file  rspl_Angular\public\web.config
  (Files in "public" are copied into the build output automatically.)
  Content:

<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <!-- API calls -> FastAPI backend (removes the /proxy prefix) -->
        <rule name="API proxy" stopProcessing="true">
          <match url="^proxy/(.*)" />
          <action type="Rewrite" url="http://127.0.0.1:8010/{R:1}" />
        </rule>
        <!-- Face photos served by the backend -->
        <rule name="Face photos" stopProcessing="true">
          <match url="^face-photos/(.*)" />
          <action type="Rewrite" url="http://127.0.0.1:8010/face-photos/{R:1}" />
        </rule>
        <!-- Angular routes: if it is not a real file/folder, serve index.html -->
        <rule name="Angular SPA" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="/index.html" />
        </rule>
      </rules>
    </rewrite>
    <staticContent>
      <remove fileExtension=".webmanifest" />
      <mimeMap fileExtension=".webmanifest" mimeType="application/manifest+json" />
    </staticContent>
    <security>
      <requestFiltering>
        <!-- allow uploads up to 20 MB -->
        <requestLimits maxAllowedContentLength="20971520" />
      </requestFiltering>
    </security>
  </system.webServer>
</configuration>

STEP C4. Build
     cd /d D:\Maruti_workspace\rspl_Angular
     npx ng build --configuration local
  Output folder:  D:\Maruti_workspace\rspl_Angular\dist\rspl_Angular\browser\
  Check that  index.html  and  web.config  are inside it.

STEP C5. Copy to the server
  Copy EVERYTHING inside  dist\rspl_Angular\browser\  to  C:\rspl\web\
  on the server (index.html must be directly in C:\rspl\web).


=====================================================================
PART D - CREATE THE IIS WEBSITE (on the server)
=====================================================================

STEP D1. Create the site
  IIS Manager > Sites > right-click > Add Website...
     Site name     : RSPL
     Physical path : C:\rspl\web
     Binding       : Type http, IP "All Unassigned", Port 80
                     (if port 80 is used by Default Web Site, either stop
                      Default Web Site or use another port, e.g. 8080)
  Click OK.

STEP D2. Application pool
  IIS Manager > Application Pools > RSPL
     .NET CLR version: "No Managed Code"   (it is only static files)

STEP D3. Folder permission
  Right-click C:\rspl\web > Properties > Security > Edit > Add:
     IIS_IUSRS  -> Read & execute
     IIS AppPool\RSPL  -> Read & execute

STEP D4. Open the firewall port (PowerShell as Administrator)
     New-NetFirewallRule -DisplayName "RSPL IIS 80" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow

STEP D5. Test
  On the server:      http://localhost/
  From another PC:    http://<SERVER-IP>/
  - Login page should open.
  - Log in with a real user -> dashboard opens.
  - Press F5 on any inner page -> page must reload (not 404).


=====================================================================
PART E - UPDATING LATER
=====================================================================

  Frontend changes:
    1. On dev PC:  npx ng build --configuration local
    2. Copy dist\rspl_Angular\browser\*  to  C:\rspl\web\  (overwrite)
    3. Users press Ctrl+F5 once.  (No IIS restart needed.)

  Backend changes:
    1. Copy the new  app\  folder to  C:\rspl\rspl_Api\app\  (overwrite)
    2. If requirements.txt changed:
          C:\rspl\rspl_Api\.venv\Scripts\pip install -r requirements.txt
    3. Restart the service (Command Prompt as Administrator):
          nssm restart RSPL_Api

  New database scripts:
    If a change adds SQL files in rspl_Api\database\ (e.g. enghub_*.sql),
    run them on the database once.


=====================================================================
PART F - TROUBLESHOOTING
=====================================================================

  Problem: Page refresh (F5) gives 404
    -> URL Rewrite module not installed (Step A2), or web.config missing
       from C:\rspl\web.

  Problem: Login gives 404 or 502
    -> ARR "Enable proxy" not ticked (Step A3), or RSPL_Api service is
       stopped (services.msc). Test http://127.0.0.1:8010/docs on server.

  Problem: "Server not reachable (500)" on login
    -> Backend cannot reach SQL Server. Check DB_SERVER in .env
       (use retailware.no-ip.org inside office) and Step A7.
       See C:\rspl\rspl_Api\service.log for the exact error.

  Problem: Backend service keeps stopping by itself
    -> Antivirus (Seqrite) may kill python.exe. Ask IT to whitelist
       C:\rspl\rspl_Api\.venv\Scripts\python.exe

  Problem: 500.19 error with web.config
    -> URL Rewrite module is not installed.

  Problem: Large file upload fails
    -> Increase maxAllowedContentLength in web.config.

  View backend logs:
     C:\rspl\rspl_Api\service.log
